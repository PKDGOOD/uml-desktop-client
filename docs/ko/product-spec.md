# UML Studio 공개 알파 제품 기획안

상태: **기획 초안 0.1 / 2026-09-26**. 구현 완료나 공개 승인을 뜻하지 않습니다. 공개 저장소의 기준 문서는 [영문 상세 기획안](../product-spec.md)이며, 이 문서는 같은 요구사항 ID를 사용하는 한국어 검토본입니다. 구현·검증 시에는 영문 상세 동작과 인수 조건까지 확인합니다.

[상세 실행 계획](../public-alpha-plan.md)은 개발 순서·의존성·일정·검증 방법을 다룹니다. 이 기획안은 **누가, 어떤 문제를 해결하려고, 어떤 기능을 어떤 방식으로 사용하는가**를 정합니다. [기존 초기 요구사항](archive/kiro-specs/requirements.md)은 이력으로 보존하고, 이번 공개 알파의 범위는 이 초안을 기준으로 확정하는 안입니다.

실제 실행 단위는 [원자 단위 실행 계획](atomic-execution-plan.md)의 **145개 하위 작업**입니다. 각 작업에 선행 조건·기획/인수 ID·완료 증거가 있으며, A01–A14는 작업 묶음으로 사용합니다.

## 1. 제품의 목적과 대상

**개발자가 작은 소프트웨어 설계를 텍스트로 작성하고, 화면에서 다듬고, 두 표현을 오가도 정보가 유지되는 로컬 UML 편집기**를 만듭니다.

주 사용자는 구현·리뷰 전에 구조와 흐름을 정리하는 백엔드/애플리케이션 개발자입니다. 보조 사용자는 프로젝트 파일을 열거나 이미지로 설계를 검토하는 동료입니다. 첫 공개 버전은 파일·이미지를 전달하는 비동기 리뷰까지 지원합니다.

아직 사용자 조사로 입증한 결과는 아닙니다. 다음 가설을 파일럿에서 확인합니다.

| 해결하려는 문제 | 제품에서 제공할 경험 | 확인 방법 |
| --- | --- | --- |
| 텍스트와 그림을 따로 고치느라 설계가 어긋남 | 같은 문서를 텍스트·캔버스에서 편집 | 두 경로로 고친 뒤 의도한 결과를 설명할 수 있는가 |
| 편집·저장 과정에서 속성이나 포함 관계가 사라짐 | 지원 속성과 원문을 보존하고 잘못된 입력을 명시 | 저장·재실행 후 의미와 배치가 유지되는가 |
| 계정 없이 설계를 보관하고 전달하고 싶음 | 로컬 프로젝트 파일, SVG·PNG, 오프라인 편집 | 다른 사람이 파일을 열고 이미지를 읽을 수 있는가 |
| 중단·저장 실패 후 남은 작업을 알 수 없음 | 파일 저장과 복구 상태를 구분 | 표시된 복구 시점까지 실제로 되살릴 수 있는가 |

첫 사용 성공 기준은 **시작 → 예제 생성 → 텍스트 수정 → 속성/연결 수정 → 저장 → 재실행·열기 → 이미지 내보내기**입니다. 설치 이후 처음 쓰는 사용자 3명 각각이 안내자 개입 없이 15분 안에 완료하는 것을 목표로 합니다. 설치 시간은 별도로 기록합니다. 현재 측정 결과가 아니라 검증할 목표입니다.

## 2. 공개 알파의 기능 범위

| 구분 | 포함 내용 |
| --- | --- |
| 공개 알파 필수 | 프로젝트·폴더·다이어그램 관리, 5종 다이어그램의 명시된 부분집합, 텍스트/캔버스 편집, 요소·연결선 속성 편집, 실행 취소, 안전한 열기·저장·다른 이름 저장, 복구·히스토리, SVG·PNG, 영어 도움말, 한글/IME, 키보드로 사용하는 폼·탐색 |
| 안정화 이후 | 최근 파일, 버전 비교, 정렬·균등 배분, 연결선 경로 직접 조정, 추가 표기법, 다른 OS의 정식 바이너리 |
| 별도 후속 제품 단계 | 요구사항 → API/상태 계약 → 계약 테스트 → CI에서 구현 불일치 탐지 |
| 이번 범위에서 제외 | 클라우드·계정·실시간 협업, 내장 AI, UML 전체 규격, PDF, 코드 생성, 플러그인, 공유 요소 편집, 대규모 지연 로딩, 고급 자동 배치 |

첫 지원 바이너리는 macOS Apple Silicon을 제안합니다. Windows/Linux 소스 CI 통과만으로 해당 데스크톱 앱을 지원한다고 표시하지 않습니다. 브라우저는 평가 모드이며 다운로드 요청을 파일 저장 완료라고 표시하지 않습니다.

### 다이어그램별 실제 기능

아래의 지원은 도구가 보인다는 의미가 아닙니다. **생성·속성 수정·연결·복사·실행 취소·저장/재열기·내보내기**까지 통과해야 합니다.

| ID | 지원할 내용 | 동작 범위와 제한 |
| --- | --- | --- |
| D-01 클래스 | 클래스·인터페이스·추상 클래스·열거형, 연관·방향 연관·의존·상속·실체화·집합·합성 | 이름·스테레오타입·가시성, 속성·메서드·매개변수·타입, 열거값, 관계 라벨·해당 관계의 다중성·방향 편집 |
| D-02 시퀀스 | 생명선, 서로 다른 생명선 사이의 동기·비동기·반환 메시지 | 메시지 라벨·양 끝·순서 편집 및 실행 취소. 자기 메시지·활성화·복합 프레임 제외 |
| D-03 유스케이스 | 액터·유스케이스·시스템 경계, 연관·방향 연관·include·extend | 유스케이스의 소속 경계를 명시적으로 지정. 액터는 경계 밖. 시나리오 자동 생성 제외 |
| D-04 액티비티 | 액션·분기·fork·join·시작·종료, 전이 | 이름·라벨·표기법 편집. 레인·객체 흐름·워크플로 실행 제외 |
| D-05 상태 | 상태·복합 상태·시작·종료, 전이 | 부모/중첩 관계를 명시적으로 편집하고 순환 금지. 직교 영역·히스토리·실행 가능한 조건식·자기 전이 제외 |

공통으로 다른 다이어그램의 요소를 연결하거나 자기 자신으로 연결하는 기능은 제외합니다. 전이 라벨의 조건은 텍스트로만 취급합니다. 다중성은 해당 클래스 관계에서만 빈 값, `*`, 음이 아닌 정수, `0..1`·`1..*` 같은 유효한 범위를 받습니다. 미지원 표기법을 읽으면 입력을 보존하고 오류를 알립니다. 내부 타입에만 존재하는 노트·UML 패키지 도형·임의 스타일을 지원 기능으로 광고하지 않습니다.

## 3. 대표 사용 시나리오: 주문 서비스 설계 리뷰

1. **Try an example → Order service**로 클래스·시퀀스 다이어그램이 있는 새 프로젝트를 만듭니다. 예제 원본은 바뀌지 않습니다.
2. 클래스의 `Order`, `OrderItem`, `OrderService`를 보고 텍스트로 `cancel(reason: String): void`를 추가합니다. 속성 패널에서 스테레오타입과 관계의 다중성을 바꿉니다.
3. 시퀀스에서 `Client`와 `OrderService` 사이에 메시지를 추가하고 라벨·순서를 바꿉니다. 텍스트와 화면, 이미지에서 순서가 같습니다.
4. `order-review.uml.json`으로 저장하고 앱을 종료·재실행한 뒤 속성·관계·순서·배치를 확인합니다.
5. 리뷰용 SVG/PNG를 내보냅니다. 편집 가능한 전달이 필요하면 프로젝트 파일을 공유합니다. DSL만 복사하는 것은 프로젝트 전체의 배치·히스토리까지 전달하는 기능이 아닙니다.
6. 별도 복구 실습에서 라벨 수정 후 복구 시각을 확인하고 강제 종료합니다. 복구본을 열어도 기존 저장 파일은 자동으로 바뀌지 않습니다.

나머지 세 예제는 시스템 경계와 외부 액터, 분기와 fork/join, 복합 상태의 내부 상태와 외부 형제를 보여줍니다. 모두 합성 예제이며 회사 설계 자료를 사용하지 않습니다.

## 4. 화면 구성과 조작

```text
새로 만들기 / 열기 / 저장 / 다른 이름 저장    프로젝트 · 저장 상태    히스토리 / 내보내기 / 도움말
다이어그램 유형별 도구
프로젝트 트리 | 다이어그램 탭                                  | 속성 패널
              | 텍스트 편집기          | 캔버스                 | 적용 / 취소
              | 인라인 오류            | 오류 시 마지막 유효본  |
선택 · 확대 비율             오류/경고                 마지막 복구 시각
```

| 화면 | 실제 기획 동작 |
| --- | --- |
| 시작 화면 | 프로젝트 생성·열기·예제·지원 범위. 가짜 최근 파일 없음 |
| 생성 대화상자 | 프로젝트/다이어그램 이름 필수, 다이어그램 유형·폴더 선택. 공백 이름 금지 |
| 작업 화면 | 기본은 분할 뷰. 텍스트 전용·캔버스 전용 전환에도 내용·선택·화면 위치 유지 |
| 속성 패널 | 선택한 요소 또는 연결선의 지원 필드만 표시. 임시 입력 후 적용·취소 |
| 문제 패널 | 다이어그램·위치·원인·수정 힌트. 클릭하면 해당 편집 위치로 이동 |
| 저장/충돌 | 취소·재시도·사본 저장·다시 읽기·명시적 덮어쓰기. 조용한 자동 덮어쓰기 없음 |
| 복구/히스토리 | 시각·종류·설명과 복구/삭제. 비어 있음·손상·저장소 오류를 구분 |
| 내보내기 | SVG/PNG, PNG 1×/2×, 전체 내용 경계와 크기 확인. 오류 문서의 이미지 생성 차단 |
| 도움말 | 오프라인 퀵스타트·5개 예제·지원 표기법·단축키·파일/복구 제한 |

1280×800과 1024×768에서 검토합니다. 좁은 창에서는 속성 패널 토글과 트리 접기를 제공하고 화면 전환이 내용을 바꾸지 않도록 합니다. 모바일 편집은 범위 밖입니다.

### 판단이 갈리기 쉬운 동작도 미리 정합니다

- **속성 입력 중 다른 항목 선택:** 적용·버리기·취소. 저장을 누르면 먼저 적용을 검증하고 잘못된 필드로 이동합니다. 한 글자마다 문서를 바꾸지 않습니다.
- **이름 변경:** ID는 유지하고 참조도 함께 바꿉니다. DSL에서 구분할 수 없는 다이어그램 내 중복 이름은 거절합니다. 공백·한글 이름은 적절히 인용/이스케이프하며, 문법이 제한된 멤버 식별자는 제약을 표시합니다.
- **포함 관계:** 도형을 경계 안으로 끌었다고 소속이 바뀌지 않습니다. 부모를 명시적으로 선택합니다. 컨테이너 이동은 자식도 함께 이동합니다.
- **복사:** 선택된 양 끝 사이의 연결과 선택 컨테이너의 자손을 포함합니다. 붙여넣기는 새 ID·충돌 없는 이름·위치 오프셋을 사용합니다. 다른 다이어그램에는 같은 유형일 때만 붙입니다.
- **탭 닫기:** 화면에서만 닫고 초안·히스토리를 유지합니다. 다이어그램 삭제는 영향 범위 안내와 사전 스냅샷이 필요합니다. 그 복원은 프로젝트 전체 복원임을 알립니다.
- **문법 오류 중 저장:** 원문 초안과 마지막 유효 모델을 함께 저장하고 `Saved · text errors remain`으로 표시합니다. 그림 내보내기는 해당 다이어그램이 유효할 때만 허용합니다.
- **다른 이름으로 저장:** 성공한 경우에만 새 프로젝트 ID와 목적지로 전환합니다. 원본과 원본의 기기 히스토리는 유지하며 새 사본의 히스토리는 별도로 시작합니다.
- **외부 파일 충돌:** 취소·사본 저장·다시 읽기·명시적 덮어쓰기. 다시 읽기 전 현재 작업을 보호하고, 덮어쓰기 전 외부 변경 파일을 백업합니다. 보호 실패 시 파괴적 동작을 막습니다.
- **복구본 열기:** 미저장 복구 사본으로 열며 기존 파일에 자동 저장하지 않습니다. 파일 저장 시각과 복구 체크포인트 시각을 따로 보여줍니다. 체크포인트에는 원문 초안과 적용한 편집이 포함됩니다. 적용 전 속성 폼은 `Not applied`로 표시하고 복구 보장에 포함하지 않습니다.
- **히스토리 용량:** 제안 기본값은 프로젝트당 최근 복구 체크포인트 2개, 자동 히스토리 20개, 기기 전체 500 MiB입니다. 수동 스냅샷과 최신 복구본은 자동 삭제하지 않습니다. 공간이 없으면 오래된 자동 기록을 정리하고, 부족하면 사용자에게 관리 동작을 제공합니다. M0 데이터로 이 기본값을 검증합니다.
- **브라우저 저장:** 다운로드 요청만으로 미저장 표시를 지우지 않습니다. 새 프로젝트로 전환하거나 닫을 때 다운로드 확인 후 계속/버리기를 명시적으로 선택해야 합니다. 브라우저 탭 닫기는 브라우저의 기본 경고를 사용할 수 있습니다. 이미지 내보내기도 프로젝트 저장으로 취급하지 않습니다.

## 6. 완료를 판정할 실제 인수 시나리오

아래는 앞으로 구현할 검증 시나리오입니다. 현재 테스트가 이미 존재하거나 통과했다는 뜻이 아닙니다. [영문 기획안의 Given/When/Then 표](../product-spec.md#6-acceptance-scenarios)에 입력과 기대 결과를 정의했습니다.

| ID | 확인할 결과 |
| --- | --- |
| AC-01 | 새 사용자가 주문 예제를 수정·저장·재실행·내보내기까지 완료 |
| AC-02 | 속성 수정 후 DSL 공백 편집·저장/열기에도 속성·주석·배치·ID 유지 |
| AC-03 | 복합 상태 내부와 외부 형제의 포함 관계 유지, 재부모 지정과 취소 정상 |
| AC-04 | 잘못된 이름·다중성·ID·참조·미래 버전을 거절하고 기존 내용 보존 |
| AC-05 | 잘못된 DSL이 탭 이동·닫기·저장·재시작 후에도 동일하게 남고 수정 가능 |
| AC-06 | 연결 수정·순서 변경·컨테이너 복사/삭제·실행 취소에서 참조와 편집 단위 유지 |
| AC-07 | 저장 취소·권한 부족·용량 부족·저장 중 편집·다운로드 취소에도 거짓 성공 없음 |
| AC-08 | 외부 변경 충돌의 모든 선택지에서 약속한 버전과 목적지 보존 |
| AC-09 | 강제 종료 후 표시했던 복구 체크포인트 이상을 복원하고 원본 파일 유지 |
| AC-10 | 폴더 삭제·스냅샷 복원·용량 초과·손상 시 보호 또는 명시적 차단 |
| AC-11 | 5종 각각의 전체 흐름과 한글/긴 라벨·관계 표기·이미지 경계 통과 |
| AC-12 | 키보드·IME·스크린리더·두 창 크기에서 입력과 탐색 검증 |
| AC-13 | 일반·스트레스·한도 초과 문서와 반복 열기/닫기에서 성능·실패 처리 측정 |
| AC-14 | 이전 파일·모델/텍스트 불일치·다른 이름 저장 사본의 이동과 복구 검증 |
| AC-15 | 실제 CI·설치/패키지·IPC/보안·오프라인 흐름의 증거 확보 |

실행 계획의 성능 목표도 함께 적용합니다. 기준 장비에서 20개 다이어그램, 다이어그램당 200요소/300연결을 대표 데이터로 삼고 명령 반응 p95 100ms 미만, 디바운스 이후 텍스트 반영 p95 500ms 미만, 열기/저장 2초 미만, 이미지 5초 미만, 캔버스 조작 30fps 이상을 측정합니다. 실제 지원 상한은 측정으로 정하며 목표치를 달성했다고 미리 표시하지 않습니다.

공개 판정은 특정 커밋의 결과를 기준으로 합니다. 데이터 변형·복구 보장 위반·거짓 저장 성공·지원 경로 크래시·조용한 덮어쓰기·완화되지 않은 도달 가능한 high/critical 보안 문제가 남으면 공개 알파 출시를 막습니다.

## 7. 스펙 주도 개발은 다음 제품 단계로 구체화합니다

공개 알파 이후 첫 사례는 **주문 취소 API**를 제안합니다. 다음 흐름 하나를 실제로 완주하는 별도 기획/RFC를 작성합니다.

**요구사항 `REQ-CANCEL-01` → 요청/사전 조건/응답/상태 인수 예제 → API 작업·상태 전이 연결 → 검토 가능한 계약·테스트 산출물 → 예제 서비스 CI 실행 → 불일치한 요구사항 ID와 기대/실제 결과 표시.**

후보 계약 형식은 OpenAPI와 명시적인 상태 전이 계약입니다. 지원 버전, 테스트 실행기, 참조 백엔드는 그 RFC에서 하나씩 선택합니다. 올바른 서비스는 통과하고, 응답이나 전이를 고의로 틀리면 실패하며, 다른 개발자가 내보낸 산출물만으로 재현할 수 있어야 완료입니다. 이 검증 전에는 UML 시각화만으로 스펙 주도 개발을 지원한다고 표시하지 않습니다.

이 단계는 현재 A01–A14 일정에 포함되어 있지 않습니다.

## 8. 구현 전에 확정할 사항

M0에서 제품 범위 채택 여부, 실제 지원 OS, 입력·이미지 한도와 기준 장비를 기록합니다. A02에서는 정확한 파일/DSL 형식과 마이그레이션을 결정하고, A08에서는 복구 저장소와 제안 보관 한도를 검증합니다. 공개 전에는 서명/공증·비공개 신고 경로·지원 여력을 확인합니다.

구현 이슈와 PR에는 **P/D 요구사항 ID → AC 인수 시나리오 → A 실행 항목 → 실제 검증 결과**를 연결합니다. 정책이 바뀌면 기획과 인수 조건부터 바꾸고 구현합니다. 현재 남은 결함은 [알려진 제한](../known-limitations.md)에 있으며, 기획서 작성이 결함 해결을 의미하지 않습니다.
